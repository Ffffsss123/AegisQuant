# 币安自动策略交易器

## 2026-10-08 连接保存与恢复

独立 App 在用户启用保存后，将币安实盘、模拟只读和模型 API 连接分别保存到 macOS 登录钥匙串，按数据目录隔离。密钥经私有管道交给稳定的 `secure-store` 组件，不进入命令行参数、浏览器存储或应用日志；没有明文回退。钥匙串锁定或连接恢复失败会显示错误并保留原记录。ChatGPT OAuth 继续使用原有 0600 文件与令牌刷新流程，不清除其登录缓存。

重启恢复连接和模型启用配置；实盘仍通过原账户身份、账户模式及持仓保护检查，并保持新开仓暂停。资金预算、亏损账本、仓位和同根 K 线防重复记录不重置。正常退出保留密钥；模型“停用并清除”删除模型记录；“清除本环境已保存的币安密钥”仅删除重启恢复记录，当前连接继续保留，要求暂停且无持仓或待核对订单。

旧版没有内存密钥导出接口。一次性迁移使用新版后台 `--credential-migration --port 8769` 并指向原 `BINANCE_TRADER_DATA`。该页无交易引擎和下单路由，只验证并保存用户重新输入的同一密钥；两项保存完成前保持旧 App 运行。模型保存执行一次小型连接测试。

ChatGPT 的模型选择以当前账户 `/v1/models` 返回的 `visibility=list` 清单为准。GPT-6.1 Sol 获得账户授权后自动出现；未授权时显示原因，不伪造可用模型。策略 API 的模型配置是独立连接。

独立于原有 moomoo 系统，主要使用 Python 标准库，白银原始PDF解析另依赖打包的 pypdf。界面与服务只监听本机 `127.0.0.1:8766`。

## 启动

双击项目目录下的 `启动币安交易器.command`，或在项目根目录运行：

```sh
python3 -m binance_trader
```

浏览器打开 <http://127.0.0.1:8766>。首次启动默认本地模拟账户300 USDT，后续恢复上次选择的环境；先保存设置，再启动策略。关闭网页不会关闭后台服务。终端按 Ctrl+C 停止服务。重启会恢复账本与持仓，但不会自动重新开启开仓。独立 App 会从钥匙串恢复已保存的实盘连接并只读核验；有未处理持仓或订单时强制显示对应环境。

## 交易环境与账户能力

| 能力 | 行情 | 交易 | 密钥 |
|---|---|---|---|
| 本地模拟（默认） | 正式市场公开API | 本机账本模拟 | 不需要 |
| 币安Demo | Demo API | 测试账户自动下单，真实调用测试API | Demo密钥 |

**实盘必须在App中单独选择、连接并确认启动。升级、切换环境及连接本身不会启动新开仓，只读连接不会自动变成交易连接。** 新通道已进行隔离的假账户成交与故障测试，没有使用用户密钥发送真实订单，尚未完成交易所实际成交验收。未完成策略历史收益验证，不提供收益保证，也不以月收益50%为优化目标。

## 策略与仓位

- 交易范围仅限黄金 XAUUSDT、WTI原油 CLUSDT、布伦特原油 BZUSDT、白银 XAGUSDT、天然气 NATGASUSDT。界面与后台均限制为这五个品种，每次只启用一个，只持有一笔。采用商品合约 TRADIFI_PERPETUAL 交易规则；Demo如未上线对应品种会拒绝开仓。
- 升级时无持仓、无未确认订单的旧配置自动切换为黄金并暂停，保留余额和风控记录；旧品种存在持仓或未确认订单时拒绝迁移，必须先核对处理。
- 可选择已收盘1分钟、3分钟、5分钟、15分钟或1小时K线；旧账本保留1小时配置。EMA20高于EMA60且收盘突破此前20根最高价时做多；反向条件做空。1分钟仅在收盘后30秒、3分钟在90秒内处理，其余周期120秒，错过就跳过。切换周期须暂停、空仓且无待核对订单，保存不会启动交易。
- 止损距离取2×ATR14与价格1%的较大值；超过8%则跳过。止盈为止损距离的两倍。只在新信号开仓，不做摊平加仓。
- 默认单笔计划损失1.5 USDT，上限3；使用账户实际 taker 费率，另预留不利滑点和资金费，按交易所步长向下取整。账户费率或保证金档位缺失、过期时禁止开仓。
- 杠杆使用整数滑块，默认2倍；上限通过币安账户 `GET /fapi/v1/leverageBracket` 按品种读取，单笔名义仓位≤150 USDT，保证金与费用预留≤可用策略预算20%。不会自动沿用币安网页中选过的倍数。
- 模拟/Demo每日（UTC）权益亏损6 USDT或相对初始300累计亏损45 USDT时，禁止开仓并尝试平仓。新实盘试运行预算为实际USDT资产余额与100 USDT上限中的较小值，累计亏损阈值为预算15%，每日为2%；预算100时对应15和2 USDT。可用余额更低时按更低数值控制开仓。已有交易记录的旧账本保留原冻结预算与亏损记录，升级不会重置。累计风控锁定不自动重置。触发价、网络故障、滑点和跳空均可能造成超额亏损。
- 订单结果未知会持久锁定，不盲目重发；同根K线不会重复开仓。网络错误暂停新开仓，恢复后需手动重新启动。

本地模拟按轮询价格加不利滑点成交，标记价格触发保护；已纳入实际发布的资金费历史和逐仓强平模型。资金费未及时公布会保留负债、预扣预留并暂停新仓，后台重试核对。它仍不是订单簿撮合模拟，不能复现离线或轮询间的价格路径及交易所实际清算执行。必须持续运行服务才能执行本地模拟止损。Demo以实际账户余额变化记账，包含实际费用和资金费；须使用专用测试账户，不要同时手动交易、划转或重置Demo余额。

## 接入币安Demo API

1. 在币安官方 Demo Trading 页面创建 **Demo HMAC API密钥**，不要把实盘密钥填入Demo配置。
2. 在本机终端运行，按提示输入（不会回显）：

```sh
python3 -m binance_trader --setup-keys demo
python3 -m binance_trader --mode demo --port 8767
```

3. 打开 <http://127.0.0.1:8767>。要求单向持仓、单资产保证金模式，无已有仓位、普通挂单或条件挂单。程序按交易对设置逐仓。
4. 点击“启动Demo自动交易”。信号出现后才下单，不会立即强制开仓。开仓后提交交易所 `STOP_MARKET` 与 `TAKE_PROFIT_MARKET` 条件单，保护单使用标记价格、关闭整个该交易对持仓。

若开仓确认后保护单失败，程序尝试一次 reduce-only 紧急平仓并锁定。若开仓响应丢失，程序无法假定成交或未成交，会锁定并要求你立即在币安Demo核对及处理。服务崩溃可能发生于成交与保护单提交之间，不能保证任何时刻都有保护。发生锁定时不要删除账本或重复启动来解除；先在官方Demo处理持仓、普通与条件订单，再由开发者核对账本。已提交的Demo保护单在程序关闭后仍由交易所管理。

## 接入实盘只读账户

在模拟环境使用只启用读取权限的HMAC密钥，不启用提现或合约交易权限，按账户要求限制IP。在App的“API连接”区域输入 Key 和 Secret，点击“连接实盘账户（只读）”。验证成功后显示余额、可用余额和持仓数；当前策略仍使用模拟资金。输入框提交后立即清空，选择启用保存后，密钥保存到 macOS 钥匙串，后台重启后恢复并只读核验。连接失败会保留此前有效的连接。密钥只送至本机服务，服务使用它向固定币安正式API主机发出签名账户查询。

以下命令是可选的旧版持久化配置方式（本机明文文件）：

```sh
python3 -m binance_trader --setup-keys readonly
```

重启服务，点击“检查实盘只读账户”。无须、也不要把API Secret发送到聊天。

也支持环境变量 `BINANCE_DEMO_API_KEY` / `BINANCE_DEMO_API_SECRET`，或 `BINANCE_READONLY_API_KEY` / `BINANCE_READONLY_API_SECRET`。密钥文件位于项目 `data/binance/`，权限0600，目录已被现有 `.gitignore` 排除。密钥仍是本机明文文件，建议使用磁盘加密。App现支持密码框输入实盘只读密钥，提交后清空；启用保存时该入口保存到 macOS 钥匙串，不在状态 API 返回；API错误不回显签名URL。

## 接入实盘交易（2026-10-04）

1. 在顶部环境选择器选择“实盘”。模拟与实盘分别使用 `paper.sqlite` 和 `live.sqlite`；切换前必须暂停、空仓且没有待核对订单。
2. 在App输入正式账户的 HMAC Key / Secret，密钥需有合约交易权限，不需要提现权限。连接只执行账户读取，检查单资产、单向持仓及账户是否可交易。使用专用账户，不要混入手工交易、其他机器人或资金划转。交易所地区、产品资格及协议须由用户在币安完成，App不会替用户接受协议。
3. 连接后显示真实USDT余额；首次实际开仓前，补充资金后可点击“查询实盘账户余额”进行只读核验并刷新初始预算（试运行最多100 USDT，重连及启动前也会重验）。账户中额外资金不会自动扩大试运行预算。首次开仓流程提交前冻结基准，之后的转账或外部交易不会重置亏损限制。更换API Key需先核对原账本，不能通过换密钥绕过亏损锁定。
4. 选择商品、单笔风险和杠杆，保存配置。保存只修改本地配置；“应用杠杆到币安”会单独确认并真实修改当前商品的杠杆，须暂停、空仓且无核对锁定。自动开仓前也会核验并应用保存的倍数及逐仓模式。
5. 点击“启动实盘自动交易”，核对弹窗中的商品与杠杆后确认。仅在策略信号、新闻与风控全部通过时真实开仓，不保证立即成交。持仓区“停止并平仓”经确认后提交 reduce-only 市价平仓，核实远端已空仓才清理保护单与本地持仓。

选择启用保存后，实盘密钥保存到 macOS 钥匙串；重启先只读核验账户，再恢复连接，不自动恢复新开仓。恢复连接后，会继续核验账本中的既有持仓；已确认的保护单由交易所执行。退出App会停止本机额外风控监控，不能将“暂停新开仓”误认为“已平仓”。

从100 USDT试运行版本起，账本的 `journal` 表持久保存完整事件及开平仓的已确认成交响应、持仓风险参数、资金费最近核验值与退出原因；界面仍只展示最近150条。费用预留明确标为预估，实际成交手续费和最终资金费需与币安账单核对，不能把预估值当实盘净收益。升级前未保存的成交细节不会补造，旧界面事件仍保留在原状态中。试运行复盘依据净收益、回撤、滑点、费用及跳过原因，参数调整不自动执行。

交易传输层仅允许五种商品必要的逐仓设置、杠杆、市价订单、条件保护单及撤单，不提供转账或提现接口。页面请求绑定当前环境和连接版本；旧页面或过期确认不能执行。HTTP请求、交易线程与进程锁一起等待完成后才能退出，避免重复后台。所有未确认写请求保留账本标记并锁定，不能盲目重试；请在币安核对持仓和订单后处理。

### 时间戳错误 -1021

交易器使用币安公开时间接口校时，把收到的服务器时间锚定到单调时钟，并留150毫秒余量，不直接用本机时间加固定偏差签名。每30秒或检测到系统时间变化、休眠时重新校时；公共时间请求禁用缓存，拒绝过期、无效或往返超过1.5秒的样本，最多重新取样三次。接收窗口仍为5000毫秒。

签名GET查询收到明确的 HTTP 400 / -1021 后，仅自动重新校时、重新签名一次。下单、杠杆、撤单等写请求及任何结果未知的超时均不自动重发。校时仍失败时会提示检查网络延迟并重新连接；不要通过删除账本解除订单核对锁定。该错误本身不能证明密钥错误。

### 账户模式检查未通过

旧提示“仅支持可交易的单资产保证金账户”合并了多个原因，不能据此认定账户正在使用多资产模式。新版连接时分别显示保证金模式、账户可交易状态和持仓模式，并列出各项未通过原因：

- `multiAssetsMargin=true` 才确认是联合保证金（多资产）；程序的逐仓风控要求单币保证金（单资产）。这与逐仓/全仓、单向/双向持仓是不同设置。
- `canTrade=false` 表示币安返回账户当前不可交易，需核对合约账户状态；不能仅凭此值断定API密钥未开启交易权限。
- `dualSidePosition=true` 才确认双向持仓；程序要求单向持仓。账户配置与专用持仓模式接口冲突时保持未确认，重新读取。
- 字段缺失、null或格式异常均显示无法核验，不当作已确认的模式，也不放行交易。

连接和诊断仅使用GET请求，不会修改币安账户模式或清空持仓。模式检查通过后还会继续检查已有仓位及挂单。币安App可在“合约 → U本位合约”的“单／联”入口查看资产模式；操作位置以[币安官方说明](https://www.binance.com/zh-CN/support/faq/detail/de2681ac63714c7d84a685967f7c1a53)及实际页面为准。

## 策略工作台实时分析

K线分析独立于下单引擎，按1秒目标周期拉取五种商品当前策略周期的K线，并显示包含未收盘K线的EMA20/60、趋势及已收盘区间/ATR；曲线包含当前K线。网络请求不重叠，接口耗时或限流时实际更新可能变慢，以成功更新时间和延迟提示为准。交易执行使用已收盘数据，结合下述新闻过滤及强平风控；展示更新不代表每秒下单。

新闻按10秒目标周期独立扫描五个商品，分别保存分析缓存；跨品种复用来源与原文缓存，慢品种不阻塞其他品种。它读取联储或EIA、BBC、Guardian的公开来源并尝试提取原始正文及发布时间。网络请求耗时可能延长实际周期，过期结果禁止新仓。切换品种不会清空其他商品的持续风险。新闻已参与开仓与退出，具体证据和阻断规则见下节；原始文章作为数据处理，不执行文章中的指令。只读接口 `/api/analysis?symbol=BZUSDT` 可查询指定商品的新闻缓存，不修改交易配置。

## 新闻与保证金风控升级（2026-10-04）

### 新闻参与交易的规则

- 新闻决策有效期75秒，可执行方向的事实证据最多6小时；持续风险的事实记录不会因六小时到期、离开RSS或应用重启而自动消失。长期背景本身不禁止开仓；新突发事件的短期交易限制另行计算。原文日期不明、旧事重报、传闻、条件句、否定句或不同品种的报道不会直接产生买卖方向；覆盖不足、抓取失败、方向冲突时暂停新仓。无持仓时数据恢复后可在所选周期的入场窗口内重新检查，尚未送单的读取失败不视为成交。
- 定向新闻需要可信官方原始利率公告，或不同独立来源对同一事实的确认。转载按原始来源合并；供应事件需匹配地区、设施和日期。库存意外仅接受同句包含实际值、市场预期和一致单位的明确事实，不臆造预期。
- 新闻来源检查正常、风险信息有效且无阻断事件，但没有可采纳的新闻方向时，显示“新闻证据不足 · 按K线判断”，允许启动策略等待已收盘K线突破。该路径需要明确的 `kline_allowed=true`，不会采纳未核验报道的多空方向，也不以盘中均线趋势直接开仓。旧版中性结果、过期快照、来源故障、重大报道正文或发布时间缺失、风险账本异常、突发冷静期不能取得此许可。2026-10-06起，方向未确认的驱动、全文已读取但规则无法提取方向的报道（包括混合转载、条件或否定表达）仅作参考，不再单独禁仓；不将它们转为新闻买卖指令。后台须明确给出K线许可，执行层与界面共同核验后才可等待收盘突破。明确新闻与突破相反仍拒单；固定品种与自动选品均要求同向已收盘突破；同向新闻、均线趋势或收盘动量不能单独替代突破开仓。两条路径均受所选周期收盘后的入场窗口限制，并继续通过账户、仓位、费用及强平距离检查。
- 已有仓位遇到确认的反向新闻，只有已收盘均线与价格动量同时反向才退出。同一根K线不立即反手。新闻断线本身不会引起追涨杀跌；止损、止盈、账户亏损保护继续运行。
- 这是可审计、有限事件词法规则，支持利率决定、特定供应中断/恢复、具备实际及预期数值的库存事件。它不是对任意文章的通用理解，也不保证经济因果或获利。来源覆盖范围会在界面明确展示；未支持的复杂事件保留为方向未确认的参考信息；Luna的逐因素解读展示在工作台因素卡片和AI面板，不因模型缺席或报错单独取消健康K线许可。

### Luna 自动新闻解读与可选人工核验

侧栏“AI新闻解读”默认预填 `http://127.0.0.1:8080/v1` 和 `gpt-6.1-sol`，填写独立的模型API密钥并保存启用后即可自动解读。模型标识依据[OpenAI Docs 的 GPT-6 Luna 说明](https://developers.openai.com/api/docs/models/gpt-6-luna)。已有自定义模型配置仍会保留，未保存的输入不会被轮询覆盖。接口采用[OpenAI Chat Completions格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，官方接口使用严格JSON Schema，第三方兼容接口保留JSON模式；模型名称必须填写服务商实际支持的名称。OpenAI官方基础地址为 `https://api.openai.com/v1`，其他兼容服务填写其文档给出的基础地址，程序追加 `/chat/completions`。尚未验证任意第三方网关兼容性，不会在失败后自动改接口或重复尝试不同参数。 本机网关支持带明确端口的 `http://127.0.0.1:端口`，直接连接 IPv4 回环地址，不进行 DNS 解析、不使用系统代理、不跟随重定向；其他 HTTP 地址和局域网地址仍不接受。网关密钥在 App 中输入并保存到 macOS 钥匙串，重启恢复连接。

“保存并启用AI分析”只配置独立的新闻解读服务，不启动策略。模型API与币安API是两套连接。配置和密钥保存到 macOS 钥匙串，不回显、不写入账本或浏览器存储；重启恢复模型连接，新开仓保持暂停。保存后会向指定服务发送当前已保存交易品种、最多8篇公开文章（每篇最多5000字符）及该品种有效的公开统计值，不包含余额、仓位、币安密钥或交易设置。模型调用可能产生费用；“测试连接”也会排队发送一条简短请求。

AI在两个独立工作线程运行，新闻源按10秒目标周期检查，K线按1秒目标周期刷新。不要求事件发生后30秒内到达，也不因报道传输超过30秒而拒绝解读；输入数据新鲜度与结果有效期检查继续生效。模型最多2个请求并发，启动间隔至少1秒；按发布者＋新闻ID＋标题/正文版本去重；RSS优先采用guid，缺失时用来源与链接生成ID。列表顺序、抓取时间、发布时间变化、空白排版变化、新闻移出再出现不会单独触发调用。只有新增ID、标题/正文更新或统计值新增/修订才调用，批次中仍可包含旧文作为上下文。没有新增不调用模型，不因15分钟届满重新分析；保留原分析时间，输入版本未变且来源健康时继续保留原解读与方向。失败版本也不自动重复请求；修复配置后重新保存可重试。去重记录仅存于当前模型连接内存，重新保存配置、断开或重启后会重新分析当前新闻；手动连接测试是独立的显式请求。没有可用正文且没有有效统计数据时不调用模型。固定模式分析已保存的策略品种，自动模式轮流分析五个品种；切换品种后展示该品种的模型结果。只有输入仍新鲜且来源读取正常的结果才显示为当前解读；修改配置、断开或正文变化时，进行中的旧任务结果不会覆盖新状态。

模型返回摘要、可能影响方向、事件分类和引用，结果自动显示。事件卡片中的“人工核验（可选）”默认收起，可按需展开引文、事件时间和原文链接；没有人工批准步骤，不核验不阻止后续分析或额外改变交易许可。Python校验格式、文章ID、完整引文是否来自输入正文、时间格式及未来时间，拒绝伪引文、工具调用、截断和无证据方向。引文先完整匹配原文，再应用展示预算：每篇文章合计最多25词、每条最多240字符；超出时不截断，而是省略该条引文并保留原文入口、事件解读和明确说明。仅展示长度超限不会让整轮失败，也不会因此再次调用模型；省略的完整引文不进入公开结果。程序依照[OpenAI Docs 结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs)，使用严格JSON Schema（官方接口）或JSON模式（兼容接口）后仍自行验证结构与证据；符合JSON格式或引用对齐都不等于事实独立成立。模型提及的事件时间会明确标为“未独立核验”，输出固定无交易权限。

AI现作为统一决策的综合方向过滤器：有效综合偏多/偏空必须与新的已收盘突破和均线、收盘动量同向，才产生候选；与独立核验新闻冲突则等待。已有仓位仅在AI反向且同向新收盘突破时产生退出候选，不能仅凭模型平仓。AI混合、不确定、过期、报错、未配置时沿用新闻规则与健康K线备用路径。AI不能取消事件冷静期或账户硬风控，不能直接调用交易接口。模型服务仍标记 trading_authority=false，表示模型不持有执行权限；本机策略消费经验证的方向投影。接口与规则测试不能证明预测准确率或收益。

### 逐因素 AI 解读（2026-10-06）

所有五个品种的因素清单随公开新闻在同一次请求中提交给已配置模型。每个因素必须返回 `analyzed` 或 `no_evidence`、方向、中文解释及事件引用下标或统计指标ID；Python拒绝缺项、重复因素、跨品种键、无引用方向与只有历史证据的当前方向。来源标题、URL和发布时间均由本地输入回填，模型不能伪造来源字段。没有相关证据显示“本批新闻未提及”；有证据但含义不明确显示“AI方向不确定”并保留模型的具体解释。状态不会伪装为事实已独立验证，也不会自动授权交易。

工作台“本品种数据与 AI 分析”将原始统计与模型解释分开呈现。已接入 [Fed H.10](https://www.federalreserve.gov/releases/h10/current/) 广义美元指数、[Fed H.15](https://www.federalreserve.gov/releases/h15/) 10年期 TIPS 实际收益率、10年期名义收益率及有效联邦基金利率；黄金另接入 [WGC / Metals Focus](https://www.gold.org/goldhub/research/gold-demand-trends) 季度全球官方净购金、金饰消费、金条金币需求、ETF净流量，以及 [SAFE](https://www.safe.gov.cn/safe/gfcbzc/) 中国月度实物黄金储备。这批宏观数据为黄金9项、白银4项公共统计；白银另新增4项年度供需指标（见下文五种商品数据链路），无需交易密钥或模型密钥即可读取。数据以原始表格数值计算前值、变化量和可比百分比，利率变化用基点；季度同比只匹配上一年同一季度。显示统计期、发布日（来源未标注则明确说明）、读取时间及源链接。

美元指数不是ICE DXY实时行情；有效联邦基金利率不等于政策目标区间或期货降息概率；中国实物储备余额变化不等同市场净购入，季度需求不是日内订单流。尚未接入的指标仍明确显示。固定新闻规则未覆盖与结构化数据状态分别记录，不能用Luna解释代替数据源。各因素数据区独立于AI服务，AI断开仍能看数值。来源读取或结构校验失败保留旧值并标注历史参考，不把旧值发送为当前指标。

Luna收到公开新闻以及有效数值指标，返回逐因素解释和 metric_ids / event_indices。指标引用只能属于该因素，返回的数值和来源由程序附加；已提供统计的因素不能以“无证据”跳过。模型文本仍可能误读，格式和引用核验不等于投资预测准确。没有新闻时也可解读有效统计。指标按ID、统计期和数值版本去重：新增或修订才分析；轮询时间、重新读取和未变的数值不会重复调用模型。模型不能直接下单；统计值与新闻进入本机统一方向策略，数值解析模块不自行修改交易或风控设置。

新闻批次读取先兼顾各因素，再补充较新报道；最多12篇正文、最多8篇模型输入，以ID与正文版本去重。真实模型端到端验收需要在当前进程配置Luna密钥，离线替身测试不冒充真实模型结果。

模型错误、等待、未启用、输入过期会清除卡片中的当前方向，历史结果明确标记为历史，切换品种不沿用上一个品种的模型结论。请求总时限45秒、输出预算5000 token，不并发，失败不自动重试；连接在完整响应后已关闭时不会再次操作失效socket。离线验证不代表预测准确率或实盘盈利验证。

### 持续风险与各品种驱动

### 每笔订单的保证金核验

1. 强制读取账户费率及保证金档位，验证维护保证金率与累计扣减额、数据有效期、行情时效及成交价与标记价差异。
2. 以不利成交和滑点估算风险，预留双边费用及三次资金费。资金费预留是预算，不是未来费率上限。初始保证金加预留不超过可用预算20%，单笔名义金额仍不超过150 USDT。
3. 根据逐仓、单向、USDT线性合约方程，迭代查找强平时所属档位。止损与估算强平价至少相隔价格0.5%、止损距离25%、两价格跳动中的最大值；不足直接拒单，不暗改所选杠杆。
4. Demo/实盘设置逐仓和杠杆后校验回复，成交后回读持仓风险和两张保护单的完整内容。真实强平价、成交风险预算或保护单不符时尝试一次reduce-only退出并锁定。开仓与保护单仍不是交易所原子事务，不能消除其间的网络故障窗口。

### AI综合方向与K线接入（2026-10-06）

`ai_policy.py` 将同品种、完整因素、依据合格且来源健康、输入版本仍一致的AI综合方向投影为只读方向过滤器；单因素偏多/偏空不会代替综合结论。模型失败、未知/混合方向和历史解读有明确备用说明；材料无新增不重新调用，无新增材料时持续复用原分析，方向投影每次须通过90秒输入健康检查。分析API、执行引擎候选、风险预算前和交易所提交前均使用同一投影并重新核对时效。

- AI与K线同向：仅在收盘后两分钟窗口内，以20根已收盘突破＋同向EMA20/60及收盘动量产生候选，仓位与费用风控仍可拒单。
- AI与突破或独立核验新闻反向：等待；不自动反手。
- AI反向退出：已有仓位需同时出现新的同向收盘突破和趋势，随后沿用交易所持仓核对和平仓流程；止损、止盈、账户亏损保护优先。
- AI无方向/混合/报错/过期：沿用已核验新闻规则，或健康新闻许可下的K线突破备用路径；不能越过来源故障或突发冷静期。
- 修改AI配置或切换分析模型要求策略暂停且无持仓/待核对订单。模型对比只使用冻结的公开材料，输出不进入策略。

模型速度/引用对比支持 `gpt-6-luna` 与 `gpt-6.1-sol`，同一批材料各请求一次；两者在官方Chat Completions中使用 `reasoning_effort=low`，无工具调用。记录耗时、结构成功、引文原文匹配数、因素覆盖及未通过引用的因素数。相同材料不会重复比较，错误不会无限重试；正常新增新闻分析优先。一次比较不能测出市场预测准确率，也不会自动更换正式分析模型。官方文档确认Sol标准输入/输出价为Luna的20倍（不计缓存）；是否升级需结合多样本质量、延迟和费用。

## Luna → Sol 独立对比试验（2026-10-08）

在项目根目录运行 `python3 -m binance_trader.news_trial_server`，打开 `http://127.0.0.1:8767/`。填写本机 `http://127.0.0.1:8080/v1` 的模型密钥后先运行一次 Luna 初筛诊断，再点击「运行五品种完整对比」。已连接时可单独点击「重新检查 Luna 初筛」；相同版本不重复付费请求。模型密钥仅在独立试验进程内存保存；交易 App 不需重启。本模块未导入生产交易链路，没有币安密钥、账户配置或下单接口，也不会替换现有 AI 结果。

试验读取原有新闻源的公开原文以及交易 App 的公开分析接口。按发布者、新闻 ID、标题与正文版本去重，五品种共享一次 Luna 提取；轮询时间、URL 跟踪参数和列表删除不创建新闻版本。指标按统计期和数值版本去重。失败版本同样不自动重试；去重状态只保留在此次试验进程内。开发修复只更改固定的 `news_trial.py` 文件时，下次手动诊断/对比会在空闲状态重载它、清空旧协议实验缓存，并在内存保留已连接密钥；正常重复点击不会清空缓存，HTTP 不接受代码路径或重载任意模块。

Luna 提取事件类型、涉及品种、简短事实、原文片段编号与事件时间。程序把正文按顺序分成不超过25词、240字符的片段，不遗漏非空白内容；模型只选编号，由程序从对应文章取回原句，不能通过改写、翻译或拼接引用通过校验。编号有效不代表事实解读正确，Sol 仍需独立复核。首次建立背景、数值指标修订，或新增重要事件、更正、矛盾和不确定事件触发 Sol。普通持续背景不会在初始化后单独触发 Sol。Luna 部分失败只剔除对应文章线索；错误ID无法归属时拒绝该批线索。缺失的初筛结果使对应品种回退到全部当前原文直接交 Sol，失败不会让整个流程永久停在初筛。新增新闻已由来源关联到某品种，但 Luna 未标记该品种时，也触发原文复核；分类器分歧不构成丢弃新闻的理由。该保护可能增加 Sol 调用，因此不能预先声称两级流程更便宜。页面逐条列出文章ID、错误字段及原因，不回显无效模型原文。Sol 同时读取原文和通过校验的 Luna 线索，仍须通过原有因素、引文和指标引用校验。未完成、失败和过期结果不作为新的有效 AI 方向；调用纯策略函数只产生研究输出，不提交订单。

同一冻结快照分别测试直接 Sol 与两级流程，交替两组请求顺序。两组均明确使用 `reasoning_effort=low` 和同一简短输出要求（保留完整因素、引文和数值引用），完整响应时限45秒；不是与旧版未指定推理强度的请求进行单变量比较。记录请求模型、网关声明的返回模型、完整耗时、用量、证据拒绝数及方向是否一致。模型名称匹配只核对网关元数据，不证明第三方的内部路由。五品种共享的 Luna 耗时只需计一次；单品种两级耗时为该共享步骤加该品种 Sol 耗时。先诊断再比较时，已完成的初筛会复用，因此需另计诊断中 Luna 的实际耗时，不把复用记作免费零延迟推理。完成时效与最终投影时效分别记录。

首轮最多1次 Luna 和10次 Sol，之后点击检查只处理新增或修订输入。结果自动写入 `reports/news-pipeline-trial-*.json`，不保存密钥、请求头或新闻全文。对照依次运行可能使后续结果过期，界面会标明仅供对照；研究采样不冒充实时交易信号。方向一致率、格式与引用通过率都不等于预测准确率，收益、手续费和滑点尚需单独验证。独立试验本身不修改交易周期或入场窗口。

验证：`python3 -m unittest discover -s binance_trader/tests -p test_news_trial.py -v`；`node --test binance_trader/tests/test_news_trial_ui.js`。离线用例使用合成模型与本机 HTTP，不消耗模型额度。

## 1分钟隔离验证与后台延迟改进（2026-10-08）

策略周期贯穿行情请求、连续性检查、已收盘信号、五品种排序、下单前复核、图表和聊天快照。切换周期清除旧缓存；延迟返回的旧周期数据不能覆盖新图表或成为入场依据。按周期保留已消费K线，并记录跨周期的最后开仓收盘时点，防止切换回来或重启后重复开仓。保护单、手续费、保证金与每日损失限制保持原有检查。

K线分析目标每1秒更新；交易线程每次执行完后等待5秒，网络和账户核验还会增加耗时。这是分钟周期策略，并非秒级成交系统。止损仍有价格1%的下限，改用1分钟并不等于已验证超短线收益、成交速度或持仓时长。

五个品种新闻分别采集和发布，目标每10秒检查。相同来源并发请求合并，RSS缓存10秒、正文缓存60秒，全局最多8个下载。慢源不会阻塞全部品种；实际轮询受源站响应限制，可以超过10秒。界面区分抓取耗时与最新文章发布时间距今；两者都不是事件发生到送达的保证。统计数据仍按各源实际日、周、月、季频率更新。

策略AI最多两个独立请求并行、启动间隔至少1秒。已知Luna/Sol配置使用低推理强度和简短完整结构输出，仍校验每个因素、原文及统计引用；请求总时限45秒，不使用部分响应作为方向。429统一退避30秒，单个品种超时不会冻结其他品种。相同输入版本不重试付费请求；无新增或修订则复用结果。待分析、失败或过期结果不提供新AI方向，K线备用路径仍须通过新闻来源健康、突发风险及交易风控检查。连接测试、完整分析、排队时间分开显示，排队从启用配置时起算。

本次实测使用直接Sol的后台分析；没有将Luna→Sol试验串联到交易路径。两级冷启动尚未证明更快。隔离验证使用独立数据目录、1分钟模拟配置、无币安密钥且自动交易暂停；升级不改变已有实盘账本的周期，不自动启动实盘。

## 持仓优先与模型用量（2026-10-08）

空仓、自动选品时，五个品种按新增或修订的公开输入分别分析。有持仓时，持仓品种优先获得空闲模型槽位，其他品种暂停常规模型调用；Python仍采集新闻、去重、更新指标、K线及风险记录，不消耗模型token。暂停新开仓不停止持仓品种的分析与原有保护。订单结果待核对时只分析对应品种，不以未知订单状态当作空仓。固定品种模式不自动分析其余品种。

未持有品种的例外为新的重大事件线索：来自原有风险规则的新突发事件，或已核验方向事实。线索和正文须仍在1小时窗口内，新闻来源健康，且相应原文已包含在模型输入中。模型仅复核事件，不获下单或换仓权限；界面在「持仓分析与机会提示」展示结果。这里是有限来源及规则监测，不能识别所有重要消息，更不能预判哪个事件会带来高收益。普通新闻、新抓取时间、长期战争背景本身不触发例外。相同事件及文章版本仅调用一次；同篇原文实质修订可再复核，其他普通新闻修订不反复唤醒同一事件。失败版本不自动重试。

重大事件提示不会改变现有持仓。按原止盈、止损、账户风控或有效反向信号退出，确认空仓后才恢复五品种比较，并重新核验时效、费用、盘口与风险；原事件提示不等于当前开仓许可。事件分析输入发生变化或结果过期时，仅保留历史提示。持仓建立前已经发出的请求允许完成，可能继续计费；不会承诺入场瞬间撤销模型费用。人工聊天、连接测试和显式模型对比不属于该自动调度。

界面显示本次模型连接的自动分析调用数，以及网关实际返回的输入/输出token累计；没有返回用量的请求明确不计入token合计，不猜测为免费。配置重存或断开会清空本次统计。此前已有「无新增不调用」去重，因此新增节省来自持仓期间忽略其他品种的普通更新。只有五份输入量相近且没有重大事件等例外时，五份减一份的常规分析才可估算约80%节省；不是账单保证。

## 开仓盘口检查

固定品种与自动选品共用开仓前盘口检查，覆盖本地模拟、Demo和实盘：点差不超过0.10%，预计不利滑点不超过0.05%，可见深度须覆盖计划数量，盘口时间与报价时间差不超过15秒。Demo及实盘在修改保证金方式、杠杆并重新计算最终数量后再次核验；异常时不发送开仓订单，保留必要的核对状态。该检查只限制新开仓，不阻止平仓或原有保护。

## 待核对请求恢复

存在待核对请求时，新版界面显示恢复面板。先点击“查询原请求结果”，只读核对原订单、账户持仓、持仓风险及未完成订单；杠杆请求另外读取当前品种的杠杆配置。条件全部满足后，可确认更新本地账本；确认前会重新查询，核对结果60秒后失效。恢复保持新开仓暂停，不重发或撤销交易所订单，不重置资金预算、亏损基准或防重复记录。

新开仓意图先持久化准备阶段，再在发送订单前持久化提交阶段。只有明确停留在准备阶段，才能确认尚未提交开仓请求。历史记录没有阶段信息且原订单查不到时，继续锁定；“查不到”不能当作未下单。非终态订单、接口不一致、未知持仓或无法验证的保护也保持锁定，需先在交易所核对处理，再返回此处查询。已终结原订单对应的持仓数量、保护单及强平距离均匹配时，可恢复原有监控，仍不开新仓。


## 桌面连接保存选择

新版原生启动器在首次启动后台前明确询问是否保存到macOS钥匙串；默认按钮为仅本次运行。菜单“API连接保存设置”可更改选择，下次后台启动生效，不会重启或中断当前连接。选择保存才启用COMMODITY_SAVE_CREDENTIALS并恢复已有钥匙串连接；恢复后新开仓仍暂停。仅本次运行不清除以前保存的项目，清除需使用连接面板中的明确操作。

## 保留账本的 API 密钥轮换

实盘暂停、空仓且没有待核对订单时，先点击“用原密钥核验账户身份”。程序只读查询原密钥的账户 UID，在原账本记录其哈希，不显示 UID。随后勾选“轮换同一账户密钥，保留原账本”，填写新密钥并确认。新密钥 UID 必须匹配，合约账户模式、持仓及未完成订单检查也必须通过。轮换不修改交易所设置、不下单，保留原资金预算、亏损额度和锁定。

请在原密钥有效时提前记录身份；原密钥已失效且没有记录时仍拒绝轮换，不能清空账本绕过。已有身份记录时，重启后即使原密钥失效，也可核验新密钥。普通连接仍禁止更换已绑定 Key；轮换失败保留原连接。启用钥匙串后，轮换成功会保存新连接；保存失败会单独提示，重启前需处理。

身份查询使用固定只读接口，需要账户读取能力，不需启用 Spot 交易或提现。接口依据：[Binance Spot 账户信息](https://developers.binance.info/zh-CN/docs/catalog/core-trading-spot-trading/api/rest-api/account)，`GET /api/v3/account` 的 `uid` 字段。
